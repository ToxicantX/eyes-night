这篇基于你给的技能清单，做一版“能直接用”的实战介绍。  
目标不是罗列功能，而是告诉你：**什么时候该用、怎么组合用、怎么避免踩坑**。

## 一、Git & GitHub 方向（5 个）

### 1) git-essentials
**定位**：Git 基础操作能力集合。  
**适合场景**：日常提交、分支管理、回滚、冲突处理。  
**建议用法**：

- 固定分支策略：`feature/* -> main`
- 每次改动前先 `status`，避免脏工作区误提交
- 破坏性操作前做备份分支

---

### 2) github
**定位**：GitHub 平台交互能力（仓库/issue/PR 等）。  
**适合场景**：跨人协作、任务追踪、发布闭环。  
**建议用法**：

- 变更先关联 issue，再开 PR
- 统一 PR 模板（变更范围、风险、验证）
- 把“讨论”沉淀到 issue/PR，减少口头丢失

---

### 3) conventional-commits
**定位**：规范化提交信息（如 `feat/fix/chore`）。  
**适合场景**：多人协作、自动生成 changelog、版本发布。  
**建议用法**：

- 提交格式统一：`type(scope): summary`
- 把“意图”写清，不只写“改了什么”
- 和 CI 规则联动，降低“可读性技术债”

---

### 4) git-sync
**定位**：本地与远端同步流程能力。  
**适合场景**：多设备开发、远端自动化发布。  
**建议用法**：

- 同步前先拉取最新变更，减少冲突
- 同步动作固定顺序：拉取 -> 校验 -> 推送
- 失败时保留冲突现场，别直接强推

---

### 5) github-pr
**定位**：PR 生命周期自动化（创建、检查、合并辅助）。  
**适合场景**：高频小改动、内容自动发布、团队评审流程。  
**建议用法**：

- PR 默认带测试结果与截图
- 小步快提 PR，避免超大改动难评审
- 合并前强制过构建/格式/检查

## 二、Browser 自动化方向（5 个）

### 6) browse
**定位**：网页读取与导航基础能力。  
**适合场景**：网页信息收集、页面结构确认、轻量抓取。  
**建议用法**：

- 先 snapshot 再操作
- 关键页面固定 target，减少串页
- 对动态页面使用状态校验（文本出现/消失）

---

### 7) webapp-testing
**定位**：Web 应用测试流程能力。  
**适合场景**：回归测试、表单流程验证、页面交互检查。  
**建议用法**：

- 把测试路径脚本化（登录 -> 操作 -> 断言）
- 明确“通过标准”，不要只看“能点”
- 保留失败截图与日志，便于复现

---

### 8) kesslerio-stealth-browser
**定位**：偏“隐身/抗识别”浏览能力。  
**适合场景**：对自动化行为敏感的网站访问测试。  
**建议用法**：

- 仅用于合规场景
- 优先官方 API，隐身浏览是备选方案
- 注意账号安全与平台条款

---

### 9) browser-cash
**定位**：浏览器会话/状态缓存类能力（常见用于复用上下文）。  
**适合场景**：重复流程中减少反复登录与重复加载。  
**建议用法**：

- 区分测试态与生产态缓存
- 定期清理失效缓存，避免脏状态干扰
- 敏感站点不要长期持久化会话

---

### 10) agent-browser
**定位**：面向 agent 的浏览器自动执行能力。  
**适合场景**：复杂网页流程自动化（抓取+操作一体）。  
**建议用法**：

- 操作前做 attach 校验
- 统一 `snapshot(refs="aria") + act`
- 固定 `targetId`，减少页面漂移重试

## 三、推荐组合（按目标）

### 目标 A：内容自动发布
`git-essentials + conventional-commits + github-pr + browse`

### 目标 B：网页流程自动化
`agent-browser + webapp-testing + browse`

### 目标 C：团队协作提效
`github + github-pr + git-sync + conventional-commits`

## 四、落地顺序（建议）

1. 先选 1 个 Git 类 + 1 个 Browser 类
2. 跑通一个最小闭环（例如“网页采集 -> 写文 -> 提交 PR”）
3. 再加测试与回滚策略
4. 最后做模板化（SOP + 清单）

## 五、常见误区

- 一次装太多技能，边界不清
- 只追求自动化，不做验收标准
- 有执行没审计，出了问题无法追踪

## 结语

这 10 个技能不是“装了就强”，而是“组合正确才强”。
先围绕一个真实业务闭环落地，再逐步扩展，你会明显感到效率和稳定性的提升。
