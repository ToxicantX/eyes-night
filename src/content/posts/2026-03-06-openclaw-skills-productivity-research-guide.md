## 二、生产力与任务管理：从“做事”到“可追踪”

### 1) task-status
**定位**：长任务状态推送与进度可视化。  
**核心价值**：把“我现在做到哪了”变成可追踪信号，减少进度焦虑。  
**适用场景**：

- 多步骤自动化任务
- 需要多人同步状态的流程
- 长时间运行（如批处理、发布流水线）

**建议落地**：

- 每个任务定义统一状态：`queued / running / blocked / done`
- 关键节点必须推送（开始、失败、完成）
- 状态消息里固定带：任务名、阶段、耗时、下一步

---

### 2) deepwork-tracker
**定位**：深度工作追踪与节奏管理。  
**核心价值**：把主观“今天很忙”转成客观“有效专注时长”。  
**适用场景**：

- 个人专注管理
- 连续创作（写作、编码、方案输出）
- 任务切换频繁导致效率波动

**建议落地**：

- 固定 45~90 分钟专注区块
- 记录中断原因（消息、会议、临时需求）
- 每日复盘只看两项：专注总时长 + 中断前三原因

---

### 3) work-report
**定位**：基于 Git/任务轨迹自动生成周报。  
**核心价值**：把“回忆写周报”改成“数据驱动周报”。  
**适用场景**：

- 研发团队周报
- 项目阶段复盘
- 个人产出归档

**建议落地**：

- 报告结构固定为：本周完成 / 风险 / 下周计划
- 自动聚合 Git 提交 + PR + issue 变化
- 周报输出后人工补充“决策理由与业务影响”

## 三、搜索与研究：从“信息输入”到“可决策结论”

### 4) exa-web-search-free
**定位**：基于 Exa 的搜索能力，偏长尾知识发现。  
**核心价值**：相比通用搜索更适合研究任务和技术资料探索。  
**适用场景**：

- 方案调研
- 技术选型
- 小众问题定位

**建议落地**：

- 每次搜索前先写“问题定义句”
- 输出时区分：事实、观点、假设
- 保留来源链接，便于复核

---

### 5) technews
**定位**：科技动态聚合与快讯筛选。  
**核心价值**：降低信息分散带来的时间消耗。  
**适用场景**：

- 每日行业快报
- 技术趋势跟踪
- 投研/内容选题

**建议落地**：

- 设置“只看高信号来源”白名单
- 每天固定时间段拉取，避免实时打扰
- 报告里必须标注“与昨日新增变化”

---

### 6) deepwiki
**定位**：快速理解 GitHub 项目结构与文档脉络。  
**核心价值**：缩短“看懂一个仓库”的冷启动时间。  
**适用场景**：

- 接手陌生项目
- 开源项目评估
- 二次开发前阅读

**建议落地**：

- 先看目录图，再看核心入口文件
- 输出结构化摘要：模块、依赖、扩展点
- 与真实代码交叉验证，避免只信摘要

---

### 7) get-tldr
**定位**：自动摘要提炼。  
**核心价值**：把长文转成“可快速决策”的短内容。  
**适用场景**：

- 长文阅读前预览
- 会议材料预处理
- 多来源信息压缩

**建议落地**：

- 摘要后必须加“原文链接”
- 对关键结论做二次核验
- 用于“缩短阅读”，不是“替代阅读”

---

### 8) agent-news
**定位**：AI Agent 方向动态监控（如 HN/Reddit/arXiv 等）。  
**核心价值**：帮助快速捕捉 Agent 生态变化。  
**适用场景**：

- Agent 产品迭代跟踪
- 技术路线情报收集
- 选题与实验方向发现

**建议落地**：

- 建立主题过滤词（编排/工具调用/评测/安全）
- 日报中保留“可落地动作”，不只报新闻
- 与团队当前路线做关联判断，避免信息噪音

---

## 四、推荐的组合打法（可直接照抄）

### 组合 A：研发周报自动化
`task-status + work-report + get-tldr`

- 任务过程中推状态
- 周末自动生成周报初稿
- 长文附件自动做摘要

### 组合 B：技术选型闭环
`exa-web-search-free + deepwiki + get-tldr`

- 先搜资料
- 再解构候选仓库
- 最后压缩成决策摘要

### 组合 C：内容运营日报
`technews + agent-news + work-report`

- 聚合今日动态
- 过滤与业务相关信息
- 自动形成日报骨架

## 五、上线前检查清单（强烈建议）

1. 这个 Skill 的输入输出是否明确？
2. 有没有来源链接与可追溯信息？
3. 失败时是否有降级路径？
4. 是否有节流策略（避免刷屏/高频调用）？
5. 是否做过最小回归（10 条真实问题）？

---

## 结语

这批 Skills 最适合的方向是：

- 把“任务管理”从主观感受变成可视化状态
- 把“信息收集”从海量浏览变成结构化决策输入

真正拉开效率差距的，不是多装几个技能，而是把它们组合成“稳定可复用流程”。
